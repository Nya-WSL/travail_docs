### 概述

设置自定义礼物的玩法规则，以及更新礼物数据。

## 配置项

| 配置项 | 默认值 | 说明 |
| ------ | ------ | ---- |
| `short_list` | `False` | 礼物列表简洁模式（存在 bug，当前版本禁用） |
| `short_time` | `5` | 简洁模式滚动间隔（秒） |

## 按钮

- **设置礼物**：打开礼物设置界面，设置自定义礼物的加时/减时/加倍/减半/清空/随机规则
- **更新礼物**：手动更新礼物数据，程序会在连接弹幕服务器后自动更新

## 玩法

- **加时**：赠送设定的礼物可以增加总时长
- **减时**：赠送设定的礼物可以减少总时长
- **加倍**：赠送设定的礼物可以增加当前总时长的一半，总时长 × 2 的礼物数量次方
- **减半**：赠送设定的礼物可以减少当前总时长的一半，总时长 ÷ 2 的礼物数量次方
- **清空**：赠送设定的礼物可以清空当前总时长，一次赠送多个礼物仅计算一次
- **随机**：赠送设定的礼物可以随机增加/减少手动设定范围的总时长，一次赠送多个礼物则每个礼物都会随机一个值，最后计算总和

### 随机权重

> 从最小数~最大数中抽取一个随机整数，每个数概率均匀分布（基于拒绝采样的梅森旋转算法），即 Python 的 `random.randint()`，在加班姬中称为默认算法。

- 随机玩法的权重可自定义：若概率分别为 0.55 / 0.3 / 0.15，则有 55% 概率减时、30% 概率不变、15% 概率加时
- 某一项概率为 0 时该项不生效（如概率为 0 / 0 / 0.15，则有 15% 概率加时）
- 其中两个概率为 0 时，这两个权重不生效（如概率为 0 / 0.15 / 0，则有 15% 概率不变）
- 三个概率均为 0 时使用默认算法
- 判断顺序为：减时 -> 不变 -> 加时
- 若某一概率为 1，则其他概率必须为 0，否则按逻辑顺序判断（如概率为 0.2 / 0 / 1，有 20% 概率减时、30% 概率加时；概率为 0 / 0.2 / 1，有 20% 概率不变；概率为 0 / 0 / 1，有 100% 概率加时）
- 概率可设为 0~1 之间的两位小数（0 和 1 除外），实际概率可能为 0.555，最终会四舍五入为 0.56
- 若随机最小数不为负数或最大数不为正数，减时/加时概率必须为 0，否则使用默认算法

### 盲盒

> 获取官方的盲盒内礼物数据需使用 cookie 鉴权，但身份码登录无法获取 cookie，因此目前会从服务器获取盲盒数据，而服务器使用小号的 cookie。
> 这种方式可能存在小号被 B 站风控或登录失效未及时刷新 cookie 导致无法获取盲盒内礼物的风险，且 B 站对 API 的管控越发严格，无法保证未来盲盒数据不会出现异常。

- 如果设定了盲盒内礼物的时长，收到该礼物时会识别为礼物本身而不是盲盒
  - 例：设定了电影票加时，未设置心动盲盒，收到电影票时将触发电影票的加时
  - 例：设置了电影票加时，设置了心动盲盒加时，收到电影票时将触发电影票的加时
  - 例：未设置电影票，设置了心动盲盒加时，收到电影票时将触发心动盲盒的加时
